# NetKit - 多合一网络工具箱

一个参考 [lucky（大吉）](https://github.com/gdy666/lucky) 的设计思路、使用相同技术栈（Go 后端 + 内嵌 Web 后台）实现的多合一网络工具。默认仅依赖 Go 标准库，WAF 模块使用 Coraza v3。

## 已实现功能

| 模块 | 说明 |
|------|------|
| 总览 | 各模块规则数、运行状态、WAF 状态、全局过滤状态一屏展示 |
| 管理后台 | Web 界面管理所有模块（默认端口 36601，默认账号 `666` / 密码 `666`），支持 **TOTP 两步验证（2FA）** |
| 端口转发 | 公网 IPv6/IPv4 TCP/UDP 转发到内网 IPv4 服务；单规则多端口；一键开关；实时日志 |
| Web 服务 | HTTP(S) 反向代理：域名子规则 + 默认兜底后端；**四种服务类型（反向代理 / 重定向 / URL跳转 / 静态文件）**；**跳转变量系统**；**UA 黑白名单**；**自定义 robots.txt**；**请求/响应头控制**；**同端口 HTTP/HTTPS 复用**；**自动 HTTP→HTTPS 跳转**；轮询/加权/IP哈希/粘性负载均衡；**失败重试**；健康检查；BasicAuth；安全组；CORS；Coraza WAF |
| 流量统计 | 每规则请求数/出入站流量/状态码分布/平均耗时/QPS/24小时趋势/热门路径/子规则维度/慢请求，界面每 3 秒自动刷新 |
| 动态域名 (DDNS) | Cloudflare / DNSPod(腾讯云) / 阿里云 / **DNSHE 免费域名**，IPv4 + IPv6 定时同步 |
| Webhook 通知 | 模板变量、事件过滤、失败重试（指数退避）、HMAC-SHA256 签名、关键字判定、界面一键测试；DDNS / 端口转发 / 全局三级 |
| 证书 | Let's Encrypt ACME v2 客户端，支持 **HTTP-01 / DNS-01** 双验证方式，**泛域名证书与多域名 SAN**，自动申请/续签 |
| 计划任务 | 内置 5 段 cron 解析器，可视化编辑，执行系统命令，手动立即执行，执行记录 |
| IP 地址库 | IP/CIDR 条目集中管理，支持备注与有效期 |
| 安全组 | 把地址库条目组成白/黑名单组，供反代子规则与全局过滤引用 |
| IP 过滤（全局） | 引用安全组做全局访问控制，可作用于后台管理访问与转发/反代入站 |
| 分组管理 | 通用分组，端口转发 / Web 服务 / DDNS 规则可归类并按组筛选 |
| 配置备份 | 一键导出全部配置为 JSON，支持拖拽还原（还原前自动留存旧配置） |
| 日志中心 | 各模块日志统一汇总，按模块/级别/关键字过滤，支持实时刷新 |
| WAF 防火墙 | 独立模块页：总开关/拦截或仅记录模式/7 组内置规则集开关/自定义 SecRule/信任 IP 跳过/规则实时测试/拦截记录 |

## 编译与运行

```bash
# 编译（需要 Go 1.21+，首次编译需可访问 goproxy.cn 拉取 Coraza）
go build -ldflags="-s -w" -o netkit.exe .

# 运行（配置文件不存在会自动创建）
./netkit.exe -c netkit.conf

# 指定后台端口
./netkit.exe -c netkit.conf -p 8899
```

浏览器打开 `http://127.0.0.1:36601`，默认账号 `666`，密码 `666`。首次登录后请立即在"设置"页修改密码。

## 使用说明

### 证书申请（ACME）
1. "证书"页 → 申请证书：填写域名（须已解析到本机公网 IP）与邮箱；
2. 申请采用 HTTP-01 验证，验证期间 NetKit 临时监听本机 80 端口，需公网可达；
3. 默认使用 Let's Encrypt；网络受限时可填自定义 ACME 目录地址（如 ZeroSSL）；
4. 申请成功后，在 Web 服务主规则中直接选择该证书启用 HTTPS。

### 证书申请（多域名）
域名栏支持填多个域名（英文逗号分隔），会申请**同一张 SAN 证书**，例如：

```
ziuzu.cc.cd, www.ziuzu.cc.cd, blog.ziuzu.cc.cd
```

所有域名需各自解析到本机且 80 端口公网可达（HTTP-01 验证）。

**关于通配符**：`*.example.com` 必须使用 **DNS-01** 验证。在证书表单里把「验证方式」选为 DNS-01，选择 DNS 服务商并填好凭据即可，程序会自动写 TXT 记录、等传播、验证、再清理。

支持的 DNS 服务商：**DNSHE**、**Cloudflare**。

DNS-01 流程：
1. 计算 `base64url(sha256(token + "." + thumbprint))`
2. 调服务商 API 在 `_acme-challenge.<域名>` 下创建 TXT（TTL 60）
3. 轮询 8.8.8.8 / 1.1.1.1 / 223.5.5.5 / 119.29.29.29 确认生效（最多等 180 秒）
4. 提交验证并轮询授权状态
5. 无论成功失败都会清理临时 TXT 记录

实测可签发真正的 Let's Encrypt 泛域名证书（`CN=*.ziuzu.cc.cd`，SAN 含 `*.ziuzu.cc.cd`）。

### 安全组 + IP 过滤
1. 先在"IP 地址库"添加 IP/CIDR 条目（可设有效期）；
2. 在"安全组"把条目组成组并指定白/黑名单模式；
3. 反代子规则可引用安全组；"IP 过滤"页把安全组设为全局过滤，并可开启"应用于后台管理访问"（开启前务必确认自己的 IP 在白名单内，本机回环始终放行）。

### WAF 防火墙（侧栏「安全」分组 → WAF 防火墙）
1. **总开关**：关闭则所有规则即使勾选也不生效
2. **工作模式**：拦截模式（命中返回 403）／仅记录模式（只记日志不阻断，适合上线前观察）
3. **内置规则集**：SQL 注入、XSS、路径穿越、敏感文件探测、漏洞利用路径、恶意扫描器 UA、恶意爬虫，可逐项开关
4. **信任 IP**：名单内的 IP 跳过 WAF 检测
5. **自定义规则**：直接写 SecRule，追加在内置规则之后
6. **规则测试**：输入 URI 和 UA 实时试跑，确认规则是否符合预期
7. **拦截记录**：查看命中的请求（时间/来源 IP/方法/URI）

配置好后，到「Web 服务」编辑规则，勾选「启用 WAF」即可保护该规则。后台自身防护需单独打开「防护后台管理自身」。

### 计划任务
5 段 cron：`*/5 * * * *` 每 5 分钟，`30 8 * * 1-5` 工作日 8:30。支持执行系统命令（Windows 走 cmd /C，Linux 走 sh -c），可设置超时、手动立即执行、查看执行记录。

### 动态域名（DNSHE 免费域名）
DNSHE（[my.dnshe.com](https://my.dnshe.com)）提供免费二级域名，API 采用「子域名 + DNS 记录」模型：

1. 登录 DNSHE 控制台 → 免费域名管理 → 左侧「API 管理」→ 创建 API Key，记下 **API Key** 与 **API Secret**（Secret 只显示一次）
2. 在控制台先免费注册要用的子域名，例如 `myapp.example.com`
3. NetKit → 动态域名 → 添加任务 → 服务商选「DNSHE 免费域名」
4. 填 API Key / API Secret，点「拉取我的子域名」可校验凭据并列出账号下的域名
5. 域名填完整子域名（如 `myapp.example.com`），按需勾选 IPv4 / IPv6

实现说明：DNSHE 的 DNS 记录挂在子域名之下，记录名用 `@`；NetKit 先查现有 A/AAAA 记录，IP 未变时跳过更新以减少 API 调用（DNSHE 限流约 60 次/分钟）。认证走 `X-API-Key` / `X-API-Secret` 请求头，接口地址 `https://api005.dnshe.com/index.php?m=domain_hub`。

### 两步验证（2FA）
设置页 → 两步验证，用任意 TOTP 验证器（Google Authenticator / Microsoft Authenticator / 1Password / Bitwarden）扫码即可启用：

1. 点「开始设置」，用 App 扫描二维码（或手动输入密钥）
2. 输入 App 显示的 6 位验证码完成启用
3. **立即保存返回的 8 个恢复码**——手机丢失时用于登录，每个只能用一次

安全机制：
- 验证码带 ±1 个时间窗口容差，容忍轻微时钟偏差
- 同一时间窗口的验证码只能用一次，防重放
- 停用需要「当前密码 + 当前验证码」双重确认，避免会话被盗后关闭防护
- 恢复码用后即焚

### 同端口 HTTP/HTTPS 复用
Web 服务规则勾选「同一端口同时接受 HTTP 和 HTTPS」（需先选择证书）后，`http://域名:端口` 与 `https://域名:端口` 均可访问，无需为 HTTPS 单独开端口。

实现方式：监听器读取连接首字节判断协议类型 —— TLS 握手（0x16 且版本为 0x03xx）走 TLS 通道，其余按明文 HTTP 处理，两条通道各自交给独立的 `http.Server`，共用同一个 handler。

### 自动 HTTP → HTTPS 跳转
勾选「自动将 HTTP 请求跳转到 HTTPS」后，明文请求返回 301/302/308 重定向到同域名同路径的 HTTPS 地址：

- 同端口模式下端口保持不变（`http://a.com:8443/x` → `https://a.com:8443/x`）
- 非标准 80 端口时保留原端口，80 端口则规范化为省略
- 可配置**例外路径**（如 `/.well-known/`），用于 ACME 验证等不能被跳转的场景

### 子规则服务类型
每个子规则可选四种服务类型（按配置顺序匹配，命中即为准；域名留空匹配全部，URL 路由留空匹配全部）：

| 类型 | 行为 | 关键配置 |
|------|------|----------|
| 反向代理（默认） | 转发到后端池，支持负载均衡/重试/健康检查 | 后端地址、权重、策略、并发、重试、健康检查 |
| 重定向 | 返回 HTTP 3xx，状态码可选 301/302/307/308（默认 302） | 目标地址（支持变量）、状态码 |
| URL跳转 | 返回 200 + HTML 自动跳转页（meta refresh + JS 兜底） | 目标地址（支持变量） |
| 静态文件 | 把 URL 路由前缀映射到服务器本地目录（自动剥离前缀） | 静态目录绝对路径 |

**跳转变量**（用于目标地址、自定义请求头值）：

| 变量 | 含义 |
|------|------|
| `{host}` / `{port}` / `{hostAndPort}` | 主机名 / 端口 / Host 头原样 |
| `{path}` / `{PATH}` | 请求路径（带 / 不带前导 /） |
| `{args}` / `{Args}` | 查询参数（带 / 不带前导 ?） |
| `{ClientIP}` / `{RemoteIP}` | 客户端 IP（可信代理头还原）/ 直连对端 IP |
| `{time}` | 当前时间 `2006-01-02 15:04:05` |

### 访问控制与头控制
对所有服务类型的子规则生效：

- **UA 黑白名单**：按关键字包含匹配，白名单只放行命中项，黑名单拦截命中项
- **自定义 robots.txt**：命中子规则的 `/robots.txt` 直接返回自定义内容（GET/HEAD/OPTIONS）
- **请求头控制**：`setHeaders` 覆盖转发给后端的请求头（值支持变量）、`appendClientIPHeader` 把客户端 IP 追加到指定请求头、`insecureSkipTLS` 忽略后端 HTTPS 自签证书、`useTargetHost` 用目标地址作为转发 Host
- **响应头控制**：`hideHeaders` 从后端响应中删除指定头、`addHeaders` 追加/覆盖返回给客户端的头（值支持变量）
- 后端地址兼容 `127.0.0.1:8080` 与 `https://…` 两种写法，前者默认按 `http://` 处理

### 分组管理
在端口转发 / Web 服务 / DDNS 页顶部的分组栏点「管理分组」即可新建、改名、删除。删除分组只解绑规则，不影响规则本身。列表支持按「全部 / 未分组 / 具体分组」筛选。

### 配置备份与还原
设置页 → 配置备份与还原：

- **导出**：下载单个 JSON，含全部 11 个配置段（注意：包含账号密码、2FA 密钥、证书私钥，请妥善保管）
- **还原**：点击选择或直接拖拽 JSON 文件，确认后覆盖配置并立即生效
- 还原前自动把当前配置存为 `netkit.conf.before-restore-<时间戳>`，可在页面下方看到列表，便于回滚

### 流量统计
Web 服务列表每条规则点「统计」即可查看：

| 指标 | 说明 |
|------|------|
| 总请求数 | 累计请求数（含被拦截和被跳转的） |
| 出站/入站流量 | 响应体与请求体字节数 |
| 状态码分布 | 2xx/3xx/4xx/5xx 占比条 + 精确计数 |
| 平均耗时 / QPS | 全量累计平均与按运行时长计算的每秒请求数 |
| 请求趋势 | 最近 24 小时每小时的请求量柱状图 |
| 热门路径 | Top N 路径的请求数、流量、平均耗时 |
| 子规则流量 | 按子规则维度的请求数、流量、错误数 |
| 慢请求 | 超过 500ms 的请求明细（方法/路径/状态/耗时/后端） |

面板打开期间每 3 秒自动刷新；支持一键清零。统计为内存累计，进程重启后归零。

实现要点：
- 用 `countingWriter` 包装 ResponseWriter 采集状态码与响应字节，同时透传 `Flusher`/`Hijacker` 保证 SSE 与 WebSocket 不受影响
- 路径统计有上限（默认 200 条），超限时按请求数淘汰最冷门条目，避免无界内存增长
- 统计在 `defer` 中统一记录，跳转/拦截/正常代理三条路径都会计入

## 配置文件

单 JSON 文件（默认 `netkit.conf`），保存即生效（规则热启停）。

## 项目结构

```
netkit/
├── main.go                      # 入口：加载配置、启动各模块与后台
├── web/                         # 内嵌后台前端（embed）
└── internal/
    ├── config/config.go         # 配置定义与原子落盘
    ├── safe/                    # 日志环形缓冲、IP 匹配、安全组解析
    ├── logcenter/               # 日志中心
    ├── portforward/             # TCP/UDP 端口转发引擎
    ├── reverseproxy/            # 反向代理（分流/轮询/认证/过滤/WAF）
    ├── waf/                     # Coraza WAF 封装
    ├── ddns/                    # DDNS 核心循环 + 三家服务商实现
    ├── cron/                    # cron 解析 + 计划任务调度
    ├── acme/                    # ACME v2 客户端 + 证书管理
    └── admin/                   # 登录会话 + REST API + 静态页面
```
